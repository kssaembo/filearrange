# 파일 정리 도우미 1.0

**AI 추천 → 사용자 검토 → 최종 승인 → 파일 이동 → 실행 취소** 흐름의 개인용 Windows 프로그램입니다.
별도 서버가 필요 없습니다. Gemini 분석에는 인터넷과 본인 API 키가 필요합니다.

## 제공 상태

- Python/PySide6 소스, Windows 단독 EXE 빌드 설정, GitHub Actions, 자동 테스트를 포함합니다.
- **이 ZIP에는 빌드된 EXE가 들어 있지 않습니다.** 현재 제작 환경은 Linux입니다.
- Linux에서 코어·Qt UI 자동 테스트를 실행했습니다. Windows 전용 DPAPI·긴 경로 테스트는 Windows 빌드 과정에서 실행됩니다.
- 실제 Gemini API 키가 제공되지 않아 실서비스 API 연결은 수행하지 않았습니다. 가짜 응답으로 요청·캐시·파싱·오류 처리를 검증했습니다.

## 1. Windows에서 EXE 만들기

### 가장 간단한 방법: 내 PC에서 빌드

1. ZIP 전체를 적당한 폴더에 압축 해제합니다.
2. 빌드할 PC에 **Python 3.12 64비트**를 설치합니다. Python Launcher도 함께 설치하세요.
3. `build_windows.bat`를 더블클릭합니다. 최초에는 인터넷으로 빌드 도구를 설치합니다.
4. 테스트가 통과하면 `dist\SafeFileOrganizer.exe`가 생성됩니다.
5. 이후에는 **EXE 하나만 실행**하면 됩니다. EXE를 사용하는 PC에는 Python이 필요 없습니다.

소스 상태로 먼저 실행하려면 `run_windows.bat`를 사용하세요.
빌드는 Windows 10/11 64비트를 대상으로 합니다. 서명 인증서는 포함하지 않습니다.

### Python을 내 PC에 설치하고 싶지 않을 때: GitHub Actions

1. GitHub 저장소 루트에 `main.py`, `organizer`, 빌드 설정 등 이 폴더의 내용을 업로드합니다.
2. `.github/workflows/build-windows.yml`도 반드시 포함해야 합니다.
3. 웹 드래그 업로드에서 숨김 폴더가 거부되면, 저장소에서 **Add file → Create new file**을 누릅니다.
4. 파일명에 `.github/workflows/build-windows.yml`을 직접 입력한 후 ZIP 안의 해당 파일 내용을 붙여 넣고 커밋합니다.
5. **Actions → Build Windows EXE → Run workflow**를 실행합니다.
6. 완료된 실행의 **Artifacts → SafeFileOrganizer-Windows-x64**를 다운로드하고 압축을 풉니다.

API 키는 GitHub에 올리거나 빌드 설정에 넣지 마세요. 완성된 앱 설정 화면에서 입력합니다.

## 2. 처음 사용하기

1. **카테고리·이동 폴더**: 카테고리를 추가하고 각각 목적지 폴더를 선택합니다.
   예: 학교업무 / 학급업무 / 수업자료 / 강의연수 / AI에듀테크 / 여행 / 가족 / 취미 / 기타.
   이름은 직접 정하며 중복할 수 없습니다. ‘판단보류’와 ‘제외’는 이동하지 않는 예약 상태입니다.
2. **설정**: Gemini API 키, 본인 계정에서 사용 가능한 모델명, 배치 크기를 입력합니다.
   모델명에는 `models/`를 붙이지 않습니다. 모델은 기본값을 고정하지 않았습니다.
3. **연결 테스트**: 가상 파일명 한 개로 API 및 JSON 형식을 확인합니다.
4. **폴더 선택**: 파일 목록을 불러옵니다. 옵션을 바꾸면 새로고침해야 합니다.
5. **AI 분석 시작**: 기본 100개씩, 설정에 따라 100~300개씩 요청합니다.
6. **검토**: 최종 카테고리 셀을 클릭하여 수정합니다. 사유는 마우스를 올리면 표시됩니다.
7. **정리 실행 · 최종 확인**: 실제 파일 수, 카테고리별 수, 모든 출발/도착 경로와 충돌을 확인합니다.
8. **위 파일 이동 승인**을 눌렀을 때만 이동합니다.
9. 되돌리려면 **마지막 정리 취소**를 누릅니다. 앱을 껐다 켜도 기록이 유지됩니다.

처음에는 파일 몇 개를 복사해 만든 연습 폴더에서 자신의 Windows 환경 동작을 확인하세요.

## 3. 빠른 검토 방법

- 체크박스: 이번 작업에서 이동할지 결정합니다. 체크만으로는 이동하지 않습니다.
- 행 선택: Ctrl/Shift로 여러 행을 선택하고 **선택 행 분류 변경**을 누릅니다.
- 최종 카테고리: 사용자가 등록한 카테고리, 제외, 판단보류만 가능합니다.
- **60% 미만**: 기본 판단보류·체크 해제. 사용자가 카테고리를 직접 지정해야 이동 후보가 됩니다.
- 60~79%는 주의 색상, 80% 이상은 일반 표시입니다. 신뢰도는 검증된 확률이 아닌 AI의 자체 추정입니다.
- 낮은 신뢰도/카테고리/확장자/선택 여부 필터와 파일명 검색을 함께 사용할 수 있습니다.
- **필터는 표시만 바꿉니다.** 화면에 안 보이는 체크된 파일도 승인 목록에 포함됩니다.
- 파일명 더블클릭: 기본 프로그램으로 열기. 실행 가능한 확장자는 추가 확인을 받습니다.
- 우클릭: 위치 열기, 해당 파일 재분석, 분류 변경, 제외.
- 사용자가 직접 지정한 분류는 AI 재분석으로 덮어쓰지 않습니다.
- 목적지와 현재 위치가 같은 파일은 실제 이동 목록에서 제외합니다.

## 4. 제외와 캐시

- **이번만 제외**: 현재 목록에서만 제외하며 다음 스캔에서는 다시 나타납니다.
- **항상 제외**: 경로+크기+수정일로 기억합니다. 표시되지만 분석·이동하지 않습니다.
- 이름/경로/크기/수정일이 바뀌면 다른 파일로 인식할 수 있습니다.
- 이동 로그 화면에서 항상 제외 목록을 초기화할 수 있습니다.
- AI 캐시: 파일명/크기/수정일/카테고리 목록/모델명 기준입니다. 동일 조건이면 API를 재호출하지 않습니다.
- 직접 지정 분류도 로컬에 저장합니다. 카테고리 삭제·이름 변경으로 유효하지 않게 된 분류는 판단보류로 전환됩니다.
- 카테고리/목적지 설정 변경 후에는 목록을 새로 불러옵니다.

## 5. 안전 동작과 제한

- 파일 내용은 분류 목적으로 열거나 읽지 않습니다. 파일 이동 자체에 필요한 OS 복사는 Windows가 수행할 수 있습니다.
- Gemini에는 임시 ID, 파일명, 확장자, 카테고리 이름만 보냅니다. 전체 경로·목적지·내용은 보내지 않습니다.
- 파일명과 카테고리명 자체에 개인정보가 들어 있으면 해당 텍스트는 전송됩니다.
- API 키는 Windows DPAPI로 현재 사용자 계정에 묶어 암호화합니다. 평문 설정 파일에 저장하지 않습니다.
- 키 저장 체크를 해제하면 이 실행 동안만 메모리에 보관하고 기존 저장 키도 비웁니다.
- SQLite 설정/캐시/이동 기록은 `%LOCALAPPDATA%\SafeFileOrganizer`에 저장됩니다. 이 DB는 파일명·경로를 포함하며 암호화 DB는 아닙니다.
- 프로그램은 파일 삭제/덮어쓰기 명령을 제공하지 않습니다. 이름 충돌은 `파일 (1).확장자` 방식으로 처리합니다.
- 스캔 후 파일 크기·수정일·파일 식별자가 달라지면 이동을 거절합니다.
- API 오류/취소 시 부분 추천을 적용하지 않고 이동을 잠급니다. 재분석에 성공하거나 새로고침 후 다시 검토하세요.
- 시스템 주요 폴더는 선택해도 경고 후 거절합니다. 숨김·시스템 파일은 기본 제외입니다.
- 목적지 하위 폴더, 심볼릭 링크, Windows 재분석 지점(일부 클라우드 placeholder 포함)은 보수적으로 제외합니다.
- 앱은 동시에 한 인스턴스만 실행할 수 있습니다.
- 파일 작업은 스캔/분석/이동/복원 worker에서 처리합니다. 이동 계획의 메타데이터 사전 점검은 승인 화면을 만들 때 수행합니다.
- 작업 중지는 현재 API 요청(최대 60초 시간 제한) 또는 개별 파일 이동이 끝나야 반영됩니다.

### 실행 취소와 중단 복구

- 파일 이동 직전에 SQLite에 경로와 상태를 기록하고, 성공 직후 완료 상태를 기록합니다.
- 일부 파일만 성공해도 성공 기록은 남으며 실행 취소할 수 있습니다.
- 원래 위치에 새 파일이 있으면 덮어쓰지 않고 번호를 붙여 복원합니다.
- 이동 후 내용 변경 가능성이 감지되는 메타데이터 변화가 있으면 자동 복원을 보류합니다.
- 파일 내용 해시를 읽지 않으므로 **크기·수정일 등을 의도적으로 동일하게 유지한 변경은 탐지하지 못할 수 있습니다.**
- 전원 차단/강제 종료로 완료 여부가 불명확한 기록은 자동으로 추측하지 않습니다.
- **이동 로그**에서 원본·대상·복원 경로를 확인하고, 탐색기에서 필요한 복구를 마친 뒤 **중단 기록 직접 확인 완료 처리**를 사용할 수 있습니다.
- 이 처리는 파일을 바꾸지 않고 해당 기록을 자동 복원 대상에서 해제합니다. 원래 로그는 남습니다.
- 미확인 중단 기록이 남으면 새 이동을 차단합니다.
- 다른 드라이브 이동은 Windows OS에 위임합니다. 네트워크/클라우드/외장 드라이브는 실제 환경 테스트가 필요합니다.
- 일반 파일 정리 도구이며 백업을 대체하지 않습니다.

## 6. 개발 구조

```text
main.py                    실행 진입점
organizer/ui.py            Qt UI, 테이블 모델, 필터, 작업 스레드
organizer/filesystem.py    메타데이터 스캔, 이동 계획, OS 이동, 복원
organizer/ai.py            Gemini REST, 배치 처리, 응답 검증, 캐시 키
organizer/storage.py       SQLite 설정·직접 분류·제외·이동 저널
organizer/secrets.py       Windows DPAPI
SafeFileOrganizer.spec     단일 EXE PyInstaller 설정
app.manifest               관리자 권한 불필요, 긴 경로 지원 선언
tests/                     코어·UI·Windows 전용 테스트
```

Gemini 모듈은 파일 경로를 API payload에 포함하지 않습니다. 향후 내용 분석은 기본 filename adapter와 분리된 opt-in adapter를 추가하는 방식으로 확장하세요. 1차 버전에는 내용·이미지·중복 분석을 포함하지 않습니다.

테스트: `python -m unittest discover -s tests -v`
Linux UI 테스트: `QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v`

## 7. 추가 제안

1. 다음 버전에서는 **로컬 규칙 우선 분류**(예: `수행평가` → 수업자료)를 추가하면 반복 API 호출을 더 줄일 수 있습니다.
2. **전송 전 파일명 가림 옵션**을 추가하면 이름·전화번호가 포함된 업무 파일명을 더 신중하게 다룰 수 있습니다.
3. **이동 계획 CSV 내보내기**를 추가하면 대량 정리 전 별도 검토 자료로 남기기 좋습니다.
